### 2.3 声纹标记 + 同对话上下文呼语推断 + 防误绑保护（PR #37 + 本次补齐）
- **交互路径**：Timeline → 展开「午后项目方向讨论」→ 点「详情」（或顶栏 `对照 · TBC` 第 1 项）。
- **核心机制**：
  - **端侧聚类 + 语义消解配合**：端侧 `3D-Speaker CAM++` 负责把同对话及跨对话的同一把声音聚成稳定簇（`94%`），大模型根据 `14:19` 对话轮次（`说话人 2` 喊 *“老陈，顺手拼个单，你点什么喝的？”* → 紧接 `说话人 1` 答 *“冰美式少冰就行”*）反推受话人 `说话人 1 = 老陈`。
  - **人物记忆卡（点气泡头像/名字打开）**：
    - 支持一键确认标记、手动改名、**合并至已有声纹档案**（如 `⇄ 合并至「阿杰」`）；
    - 支持 **「本段不是他（防串音解绑）」**：嘈杂环境下单段串音可单独解绑当前对话，不污染已绑定的全局声纹簇；
    - 展示随对话累加的人物资料（如饮品偏好、排期主张、协作习惯），且**每条关联对话均可点击溯源回原话**。
  - **区分「在场说话人」与「不在场被提及人」**：如周一例会提到 *“让第三方对接方提前给测试账号”*，仅建立无声纹的语义实体卡，绝不误绑现场说话人声纹。

### 2.4 三元记忆图谱：日间清洗提取 + 夜间做梦编织（PR #37 + 本次补齐）
- **交互路径**：`Setting → 声纹与记忆图谱` 二级页，或任意对话详情页底部的「日间清洗 · 记忆图谱候选提取」。
- **三层图元（属性超图 / 边物化时序图谱）**：
  1. **实体 / 对象（Entity）**：人（老陈、阿杰、待确认张总、未在场提及人）、物（电影《007黄金眼》）、团队私有概念（「可验证小方案」「10% 晚八点窗口」，并自动反哺日间润色热词表做同音纠偏）；
  2. **关系（Relation · 图的“边”升格为“点”）**：高频或承载复杂互动的连接边升级为独立关系节点（如 `老陈 ⇄ 小周 · 排期裁决与分工搭档`、`我 ⇄ 阿杰 · 灰度发布上线协同`），包含**互动属性、状态新陈代谢（`当前生效` vs 删除线 `历史归档`）与可点击溯源的关联事件链**；
  3. **事件脉络（Event / Story）**：作为所有记忆结论的时空事实锚点（Provenance）。

### 2.5 「日报」升级为「睡前日记」+ 1～5 项睡前轻标注（PR #37）
- **交互路径**：Timeline 今日分组顶部「今日睡前日记」（内含「今日 / 昨日睡前日记」切换）。
- **核心机制**：
  - 摒弃枯燥的自动会议总结，用有温度的叙事串联今天做过的事，每段附 `✦ App 记录与上下文推理` 并支持点赞（`♡ 记准了` → `♥ 已赞`，上调该类推理偏好权重）；
  - 每次附带 **1～5 个需要用户拍板的轻标注点**——专挑大模型单靠历史记录无法证明或证伪的推测（示例给出了 3 项：① 确认新声纹是否为「老陈」、② 判断 13:05 窄带电话声纹 `76%` 是否与上周三「张总」为同一人、③ 确认 `14:26` 单击物理键是否为排期拍板打点）；

  - **重复事项洞察与 Skill 养成**：识别用户在 `10/29`、`11/05`、`昨日 09:30` 连续 3 次人工核对同一组灰度三要素，主动提醒下次交由 Agent 通过 `Skill · 灰度发布三要素核查 v1.3` 自动处理并随做梦持续完善；

### 2.7 录音卡物理按键 × 灵动岛收听 × A/B 双阶段系统消息推送（PR #37）
- **交互路径**：Timeline 底部快捷预览条、右上角硬件弹层内快捷条，或 `Setting → 物理按键与灵动岛 Agent`。
- **三类手势定义**：
  - **单击（Single Press）= 打重点（Mark）**：日常无感盲按，不响提示音打断对话；灵动岛轻闪记录锚点，大模型在总结与睡前日记中重点留意并推测此处意图；
  - **长按（Long Press）= 语音命令（Command / Action）**：无需掏手机解锁，按住直接说话唤起顶部**灵动岛**波形收听（如问 *“前几天看的电影是什么名字？”*），松手后先后弹出两条系统级推送通知：
    - **推送 A【立即】**：`我现在就去查一下，找到和你说。`
    - **推送 B【结果】**：`找到了，是《007黄金眼》，在前天，9 月 5 日周三下午看的，你还吃了爆米花。`（附「查看记忆 ›」直达记忆图谱）；
  - **双击（Double Press）= 暂空预留**：留白待后续绑定自定义快捷事件。

#### Q2 · 机主本人（「我」）的声纹如何首次建档？
- **背景**：在对话里别人很少直呼机主全名，但区分「我说的话（机主承诺的待办、个人观影口味）」与「对方说的话」对睡前日记第二人称叙事（“你今天答应了…”）和记忆归属至关重要。
- **候选方案**：

#### Q3 · 声纹跨对话自动指认的置信度阈值与纠错策略
- **背景**：电话外放、会议室远场回声会导致 CAM++ 余弦相似度波动。

### 二、三元记忆图谱与隐私边界

#### Q4 · 关系「边」升格为独立「点」的触发条件，以及旧状态覆盖策略
- **背景**：如果每次普通对话都把关系升格为节点，图谱会迅速膨胀成噪音网。
- **推荐默认方案**：满足任一条件时由夜间「做梦」管线将边升格为节点：① 同一对实体跨 **≥ 2 场独立事件**产生协作/互动；② 单场对话内围绕该关系出现**明确分工承诺、排期裁决或物理键单击打点**。当后续事件推翻旧结论时（如“首版含导出”→“导出延后两周”），**不物理删除旧记录**，而是将旧属性标为 `archived`（历史归档态，带时间戳），新属性标为 `active`（当前生效态）。
> **Owner 回复**：

#### Q5 · 隐私红线下，三元记忆图谱与人物资料保存在哪里？
- **背景**：`AGENTS.md` 硬约束规定 *“音频切片、转写文本、声纹 embedding 默认只在本机；云端只上行润色/总结所需的文本”*。而「长按按键问 Agent 前几天看的电影」需要在历史记忆图谱中检索。
- **候选方案**：
  - **A（全本地 SQLite 图存储 + 按需检索片段上云推理）**：声纹向量 + 三元记忆图谱（节点/边/事件索引 + 本地 FTS5 全文/向量检索）全部落手机本地 SQLite；日间清洗、夜间做梦、长按提问时，本机先检索出相关的 Top-K 记忆卡片与文本片段，随当次请求发给云端模型网关推理，网关无状态不落库；
  - **B（云端同步加密图谱）**：记忆图谱同步到后端账号名下（支持换机/多端共享），声纹原始音频与向量仍留本机。
- **推荐默认方案**：**现阶段采用 A（本机 SQLite 持久化 + 支持随导出备份）**，完全贴合当前无状态模型网关架构与本地隐私红线；若未来要做多端同步再单独开开关。

#### Q9 · 修改长按为「语音命令」后，与固件原默认按键行为如何解耦？
- **背景**：在 `reai-card-sdk` 中，出厂固件可能默认把 `btn_long_press` 绑定为 `record_toggle`（长按开关录音）。如果直接把长按改为 Agent 语音提问，必须把固件 KV 里的 `btn_long_press` 改绑为 `none`（不停止当前录音），把 `btn_single` 绑为 `record_mark`（设备侧原生打点，哪怕蓝牙断连也能写进录音元数据）。那么硬件侧开关录音靠什么？
- **推荐默认方案**：
  - **有侧边拨杆开关的机型（录音卡带物理拨杆 `TOGGLE_SWITCH`）**：拨杆负责开关录音；圆按钮专职交互（单击=`record_mark`，长按按下~松手=Agent 语音指令，双击=预留）；
  - **无拨杆仅单按键机型（若有）**：是否仅在「已在录音中」时长按触发 Agent 提问，或改用其他组合？请确认当前主力硬件（DYJV2）是否统一由侧边拨杆管录音开关。

#### Q10 · 长按说话时，收音走「录音卡麦克风」还是「手机麦克风」？
- **背景**：用户目标场景是 **“不用拿起手机，直接按住录音卡按钮说话”**（此时手机大概率揣在裤兜或包里，手机自身麦克风隔着衣物收音极糊，且 iOS 后台锁屏状态下 App 无法随意抢占手机麦克风录音会话）。而 `card_bridge` 已经实现了 `realtime.open`（`RECORD_REALTIME_ENABLE(true)`，通过 BLE 实时下发 16kHz PCM 音频块）！
- **推荐默认方案**：**优先走录音卡麦克风实时 BLE PCM 流**——收到 `LongPress` 事件瞬间开启（或复用已开启的）`realtime` PCM 流截取 `LongPress → LongRelease` 之间的音频片，送入本机 SenseVoice 秒级转写后立刻发推送 A【立即回执】，同时调记忆检索 + 大模型生成结果后发推送 B【结果】！全程手机揣兜里锁屏也能清晰收音。

#### Q11 · iOS 锁屏/后台下「灵动岛（Live Activity）」与「A/B 两条推送」的系统权限边界
- **背景**：在 iOS（ActivityKit + UserNotifications）下：
  1. **A/B 两条系统消息推送**：App 在后台因 BLE 事件被唤醒（`bluetooth-central` 后台模式已开启）时，直接通过 **`UNUserNotificationCenter` 本地通知（Local Notification）** 即可毫秒级弹出推送 A（*“我现在就去查一下，找到和你说”*），几秒查完后再弹推送 B（*“找到了，是《007黄金眼》…”*）——**无需绕服务端 APNs，延迟最低且锁屏/Apple Watch 均能收到**；
  2. **灵动岛（Live Activity）**：iOS 限制后台进程不能从零调用 `Activity.request()` 新建灵动岛（除非前台已驻留一个录音卡连接态 Live Activity，或通过 Push-to-Start APNs Token 唤醒）。
- **推荐默认方案**：
  - 当录音卡蓝牙连接成功（或开启持续守护模式）时，建立轻量常驻/挂起态 Live Activity（平时折叠不打扰，长按 `LongPress` 时通过后台 `activity.update()` 立即展开灵动岛收听动效，`LongRelease` 查完后收起）；
  - 若用户系统关闭了 Live Activity 权限，自动优雅降级为**仅弹 A/B 两条系统推送通知**（核心免掏手机体验 100% 可用）。
